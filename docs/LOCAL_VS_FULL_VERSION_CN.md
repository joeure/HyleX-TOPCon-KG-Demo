# 本地验证版与完整全量版的主要差别

本地验证版用于比赛评审和功能复现。它保留了项目最核心的可验证流程：

```text
文档 → Chunks → Ontology/KG 候选 → 人工审核 → Snapshot → 查询与证据回链
```

两者的主要差别如下：

| 本地验证版 | 完整全量版 |
|---|---|
| 只包含完全合成的 Toy 文档、Ontology 和 KG | 可管理经授权的完整业务知识资产 |
| 使用轻量文件状态和本地对象存储 | 使用面向持续运行、扩展和迁移的完整存储体系 |
| 仅提供 Inspector 所需的最小 Core、Query 和 Gateway 能力 | 包含更多运营、管理、评估和扩展能力 |
| 不包含 PostgreSQL、Neo4j、MinIO、MinerU、Streamlit、Evaluation 等独立组件 | 可按部署需求启用完整服务拓扑和外部基础设施 |
| 只有受限的 `demo` 用户 | 支持更完整的用户、角色和管理流程 |
| Provider 由评委通过本地文件和 CLI 自行导入 | Provider 可按完整系统的治理流程管理 |
| 面向单机、小数据量、短期评审 | 面向持续运行、更大数据量和多工作流协作 |
| 后端以评审二进制镜像交付，Inspector UI 提供源码 | 完整版本的源码、配置和数据不属于本评审包交付范围 |

本地验证版不是完整生产部署，也不用于性能、容量或生产安全基准测试。它的目标是
让评委在不接触真实数据和项目方凭据的情况下，验证主要界面、知识生产闭环、
Snapshot 一致性以及 Evidence 可追溯性。
